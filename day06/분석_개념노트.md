# day06 분석 개념 노트

`day06/project_v1/`의 실제 실습 코드와는 별도로, 데이터를 마주했을 때 "어떤 문제를 풀 것인가"를 정하는 사고 과정을 채팅에서 정리할 때마다 이 파일에 누적한다.

## 1. 문제 후보를 정의하는 체크리스트

새 데이터셋을 받으면 무작정 모델링을 시작하지 않고, 아래 세 가지를 먼저 한 줄씩 채워서 후보 문제를 여러 개 나열한다.

- **무엇을 맞히는 문제인가**: 입력(공정 조건 등)으로 무엇을 예측/판단하는지 한 줄로
- **결과 열로 무엇을 쓰는가**: 실제 CSV에 있는 열 이름만 사용. 없는 열을 지어내지 않는다
- **현장에서 누가 그 판단에 쓰는가**: 예측 결과를 실제로 소비하는 역할(엔지니어/팀)을 명시 — 이게 채워지지 않으면 실무적으로 의미 없는 문제일 가능성이 높다

### 예시 (`data/day06_semiconductor_yield.csv`, 2026-08-21 논의)
- 수율 예측(회귀): 결과 열 `yield`, 사용자는 공정 엔지니어(PE)
- 결함 수준 예측(회귀/분류): 결과 열 `defect_count`/`defect_density`, 사용자는 결함검사/수율관리 엔지니어
- 전기특성 예측(회귀): 결과 열 `leakage_current`(대안 `vth`, `resistance`), 사용자는 E-test 엔지니어

## 2. 입력(feature)과 결과(target) 구분

공정 조건류 열(예: `etch_rate`, `pressure`, `temperature`, `exposure_time`, `focus_offset`, `dose`, `deposition_rate`, `thickness_uniformity`, `implant_energy`, `tilt_angle`, `critical_dimension`, `oxide_thickness`, `resistivity`)은 원인 쪽(입력)에 가깝고, `yield`, `defect_count`, `defect_density`, `vth`, `leakage_current`, `resistance` 같은 결과 지표는 결과 쪽(타깃) 후보다. 문제를 정의할 때 이 둘을 먼저 구분해두면 "무엇으로 무엇을 맞히는가"가 명확해진다.

## 3. 회귀 vs 분류 판단 기준

- 결과 열이 연속값이면 기본은 회귀 문제(예: `yield`, `leakage_current` 값 자체를 예측)
- 분류로 바꾸려면 연속값에 임계값을 적용해 이진 라벨을 새로 만들어야 하는데, **임계값은 데이터 분포를 보고 정해야 하며 임의로 지어내지 않는다** (참고: `day03`에서 `result` → `불량여부`로 변환한 방식과 동일한 사고)

## 4. 주의사항

- 실제 열 이름만 사용하고, 없는 열이나 라벨을 지어내지 않는다
- "현장에서 누가 쓰는지"가 애매하면 그 문제 후보는 재검토 대상

## 5. "공정기술 엔지니어(PE)가 가장 주로 하는 일"에 가장 가까운 후보 (2026-08-21 논의)

3개 후보(수율 예측 / 결함 수준 예측 / 전기특성 예측) 중 PE 업무에 가장 가까운 것은 **결함 수준 예측(`defect_count`/`defect_density`)**.

- PE의 일상 업무는 자신이 담당하는 공정 단계(식각/노광/증착/이온주입)의 레시피 파라미터를 조정하는 것인데, 데이터셋에 단계별 담당 설비 열(`etch_tool`, `litho_tool`, `deposition_tool`, `implant_tool`)이 그대로 있음 → `defect_count`/`defect_density`를 예측하면 "어떤 조건·설비에서 결함이 느는가"를 바로 그 설비/레시피 조정으로 연결할 수 있어 PE가 매일 하는 원인→결과 루프와 직접 맞닿음
- `yield`는 여러 공정 단계를 다 거친 뒤 나오는 최종 결과라 PE 한 명이 단독으로 소유하기보다 수율관리/통합 조직이 종합해서 보는 지표에 가까움
- `leakage_current`/`vth`는 웨이퍼가 E-test 단계까지 간 뒤에야 나오는 값이라, PE보다는 전기특성/E-test 엔지니어의 영역이고 시점도 PE의 공정 조정 타이밍보다 뒤에 있음
